# screenshot-ocr Specification

## Purpose

战绩截图是记录一场游戏结果的原始图片。本能力定义截图上传、OCR 识别管线（Windows 客户端本机识别 + 服务端识别）、老板昵称匹配、草稿与确认入账、去重与重新识别的行为规则。

## Requirements

### Requirement: 本机 OCR 识别

Windows 客户端必须（SHALL）在本机执行 OCR：使用 Windows WIC 在内存中解码图片，ONNX Runtime CPU 执行 PP-OCRv6 模型，C++ 完成文字检测后处理、CTC 解码与战绩表几何解析。识别过程不将原图写入临时文件；模型与推理库随安装包分发，识别时加载、结束后释放，不需要用户安装 Python、OpenCV 或下载模型。导入时本地识别和原图上传同时进行，服务端按原图 SHA-256 校验识别结果。

#### Scenario: 本地识别上传

- **WHEN** 用户在 Windows 客户端导入一张战绩截图
- **THEN** 本机完成识别，同时原图上传服务端，服务端按 SHA-256 校验识别结果

#### Scenario: 识别资源随包

- **WHEN** 检查 Windows 安装包与程序目录
- **THEN** 包含 OCR 模型与原生推理库，不包含 Python、NumPy、OpenCV 或后台模型进程

### Requirement: 服务端 OCR 兼容

系统必须（SHALL）保留服务端 OCR（RapidOCR / Python）供浏览器预览与旧客户端使用。截图在后端按识别服务的单 worker 容量排队，排队和识别各有 35 秒上限；服务返回可重试的繁忙响应时有限重试。界面必须区分服务繁忙、超时、没有文字和没有定位到队员行。没有 OCR 服务时仍能保存原图和人工校对。

#### Scenario: 服务繁忙

- **WHEN** 识别服务返回可重试的繁忙响应
- **THEN** 后端有限重试，最终仍繁忙时界面上明确区分「服务繁忙」而非识别无结果

#### Scenario: OCR 不可用

- **WHEN** OCR 服务不可用，用户上传截图
- **THEN** 系统仍保存截图草稿和原图，可由人工校对完成入账

### Requirement: 战绩解析范围

系统必须（SHALL）针对三角洲行动的战绩详情表解析「带出价值」列和队员撤离状态。监狱地图的「越狱成功」「越狱失败」分别沿用撤离成功、撤离失败规则。其他界面或裁掉表头的截图可能需要人工补录；识别结果必须经人工确认后才入账。

#### Scenario: 越狱状态映射

- **WHEN** 截图来自监狱地图，结果为「越狱成功」或「越狱失败」
- **THEN** 系统分别按撤离成功、撤离失败解析

#### Scenario: 无法解析

- **WHEN** 截图不是支持的战绩详情界面或缺少表头
- **THEN** 系统不伪造结果，保留原图并允许人工补录

### Requirement: 老板匹配与归单

系统必须（SHALL）按截图昵称匹配老板：区分大小写，除两端空白外要求昵称一致；历史截图保留导入时的昵称。未匹配到老板时保留草稿。截图导入选择器只列出进行中的护航单和单局单，过滤已完成与已归档订单。

#### Scenario: 未匹配保留草稿

- **WHEN** 截图昵称未匹配到任何老板
- **THEN** 系统保留未归属草稿，不丢弃截图，可后续补录

#### Scenario: 目标订单过滤

- **WHEN** 用户在截图导入时选择目标订单
- **THEN** 选择器只提供进行中的护航单和单局单，已完成与已归档订单不出现

### Requirement: 草稿与确认入账

系统必须（SHALL）保证截图只有确认后才进入账本：识别值不直接扣账，人工核对原值并明确假账扣除后才入账。原图与识别结果先保存，界面只显示原图和本场结果。尚未确认的截图可从「待确认截图」继续填写，仍在同一订单内。识别失败保留原图、草稿和已填写结果；已有失败草稿可在同一记场面板「重新识别」，重新识别保留已保存的人工结果和假账扣除。

#### Scenario: 待确认继续填写

- **WHEN** 订单存在待确认截图，用户从「待确认截图」进入
- **THEN** 在同一订单内继续校对并确认入账

#### Scenario: 重新识别保留人工结果

- **WHEN** 用户对已有草稿点击「重新识别」
- **THEN** 重新识别保留已经保存的人工结果与假账扣除，识别失败也不丢失原图和已填内容

### Requirement: 去重与上传约束

系统必须（SHALL）按原图内容去重：重复上传或确认不重复扣账，已完成的重复图不覆盖既有结果。上传接受 PNG、JPEG、WebP，原图最大 12 MiB、4000 万像素；上传请求使用与 API 一致的 18 MiB 信封上限。结果同步中断可通过重复上传或重新识别恢复。

#### Scenario: 重复上传

- **WHEN** 用户重复上传同一张已入账截图
- **THEN** 系统识别为重复，不产生第二条流水，也不覆盖既有结果

#### Scenario: 超限拒绝

- **WHEN** 上传图片超过 12 MiB 或 4000 万像素
- **THEN** 系统拒绝并提示，不进入识别流程

### Requirement: 截图预览与查看

系统必须（SHALL）在对局记录旁按需加载 OSS 生成的 WebP 缩略图（216×122 像素以内、质量 80），图片在记录进入可视区域时读取；点击后才读取完整原图，两种图片分别缓存和重试，同一条记录重复打开复用已读取原图，支持 Esc 关闭。已完成和已归档订单同样支持查看。

#### Scenario: 缩略图分流

- **WHEN** 对局记录进入可视区域
- **THEN** 系统加载缩略图而非完整原图；点击后才请求完整原图

#### Scenario: 独立重试

- **WHEN** 缩略图或原图加载失败
- **THEN** 可分别重试对应图片，互不影响
