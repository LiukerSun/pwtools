## Why

现有第三方接口只能查询已收录方案，用户提供的 M7 改枪码未被收录时无法获得属性。用户的枪支属性截图已经能被现有 OCR 模型读取，需要增加专用字段解析和人工校对保存，建立账号自己的属性记录。

## What Changes

- 在改枪码添加/编辑面板增加截图选择、剪贴板粘贴、识别预览、属性手动填写和确认保存；支持完整码和核心码，截图不含代码或模式时沿用用户填写的信息。
- 增加枪支属性面板解析，覆盖八项主要属性及容量、开火模式、枪口初速、枪声传播距离和截图参考价，识别值与单位分开处理，缺失字段允许补录。
- Windows 复用本机 OCR 模型与推理库，增加专用属性解析入口；浏览器复用服务端 OCR 引擎，增加仅返回候选值的识别接口。
- 增加账号私有属性保存接口契约，将用户确认后的快照保存在数据库；优先展示个人属性，第三方目录结果保留为独立来源，不能自动覆盖个人属性。
- 属性截图仅用于内存识别和本次校对，取消后不保存图片、OCR 文本或属性；确认保存也不持久化截图，不增加 OSS 归档。
- 影响关联能力：现有改枪码能力位于已完成但尚未归档的 `openspec/changes/add-weapon-build-codes/specs/weapon-build-codes/spec.md`；复用 `openspec/specs/screenshot-ocr/spec.md` 的推理基础设施，但新增独立解析入口，不改变战绩识别与入账要求。

## Capabilities

### New Capabilities

- `build-code-attribute-ocr`: 改枪码属性截图识别、人工校对、私有快照保存、来源优先级、身份绑定及兼容行为。

### Modified Capabilities

无现有主规格需求需要替换。`weapon-build-codes` 目前尚未合入主规格，本变更以已发布的 0.9.40 实现及其已完成变更为基础，用新增能力定义扩展行为，避免重复创建基础管理需求。

## Impact

- 前端：`WeaponBuildCodes.tsx`、属性展示样式、共享契约、浏览器 API 与原生 RPC，复用截图选择/剪贴板交互，不走战绩上传流程。
- 原生：`local_ocr.*` 抽取通用文字识别结果，新增枪支面板解析器及桥接方法；保持现有 `Recognize` 战绩语义、资源释放和图片限制。
- 服务端：Rust `weapon_build_codes.rs` 的输入校验、存取和有效属性选择，OCR 客户端的专用调用，Python OCR 服务的专用解析与入口；新增可空个人属性字段迁移。
- 存储：仅 PostgreSQL 保存确认后的个人属性和来源时间，依旧按账户隔离；图片不进入截图表、OSS、对象队列或账本归档。
- 兼容：旧客户端继续读有效 `attributes`，不带新字段的修改不得擦除同一方案的个人属性；第三方 Token 可选。
- 不增加 OCR 模型、Python 桌面依赖或外部服务。截图价格是游戏内参考价格，不是人民币收入；不改变订单、租号、转单、入账或账本余额口径。
