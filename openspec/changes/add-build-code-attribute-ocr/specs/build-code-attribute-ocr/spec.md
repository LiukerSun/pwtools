## Purpose

为第三方目录尚未收录的改枪方案提供账号私有的属性录入能力。用户通过属性面板截图识别或手动填写并校对后，将属性与当前改枪码绑定保存，保留来源、单位与时间，使后续查看无需重新查询第三方目录。

## ADDED Requirements

### Requirement: 属性截图识别与手工补录

系统必须（SHALL）允许已登录用户在改枪码添加或编辑面板选择 PNG、JPEG、WebP 属性截图或粘贴剪贴板图片，显示本次截图预览和可编辑的识别候选。用户必须能够不提供截图直接手工录入属性，截图缺少代码或模式时必须由用户填写或保留当前草稿值。识别不得自行生成改枪码或推断模式。

#### Scenario: 未收录 M7 方案识别
- **WHEN** 用户填写 `M7战斗步枪-烽火地带-6LHDKCC036I65F2DQBEVD` 并导入含该枪属性面板的截图
- **THEN** 系统生成该草稿的属性候选并允许校对，不以第三方未收录为识别或保存的阻碍

#### Scenario: 核心码与手工录入
- **WHEN** 用户仅填写核心码并手工补充枪名、模式与属性
- **THEN** 系统允许确认保存，缺少枪名或模式时阻止保存并定位输入错误

#### Scenario: 文本粘贴不被接管
- **WHEN** 用户在改枪码或备注文本框粘贴文字
- **THEN** 系统保持文本粘贴行为，不触发图片识别

### Requirement: 标签与单位正确解析

系统必须（SHALL）支持基础伤害、护甲伤害、优势射程、后坐力控制、操控速度、据枪稳定性、腰际射击精度、射速，以及容量、开火模式、枪口初速、枪声传播距离和截图参考价。识别必须以标签与对应数值的位置关联，正确处理千位分隔、米、发/分、米/秒和开火模式；缺失、冲突、重复候选或低置信值必须保持待核对状态，不得取无关数字或条形长度伪造值。

#### Scenario: 标准 M7 面板
- **WHEN** 导入等价于已提供样本的清晰面板，包含价格852,355、基础伤害39、优势射程65米、后座61、操控38、稳定63、腰射51、护甲伤害42、射速649发/分、容量30、全自动/单发、初速819米/秒和传播距离600米
- **THEN** 系统将各标签与对应数值和单位正确绑定，涂装数量5及初始属性图例不进入属性结果

#### Scenario: 部分面板或数字冲突
- **WHEN** 截图裁掉射速或同一标签出现无法可靠区分的多个数值
- **THEN** 对应字段为空或标记待核对，其他已明确字段仍可校对，缺失字段不显示为0

### Requirement: 识别位置与图片资源限制

系统必须（SHALL）在 Windows 客户端复用随包本机 OCR，在浏览器通过鉴权后的服务端接口识别。图片必须沿用12 MiB、4000万像素及支持格式限制，大图片请求不得放宽普通表单限制。本机识别不得要求额外安装 Python、下载模型或上传原图；服务端识别必须共享现有 OCR 容量控制，繁忙、超时、无文字和无法识别面板必须可区分并允许手工补录。

#### Scenario: 本机识别
- **WHEN** Windows 客户端识别属性截图
- **THEN** 在本机内存完成推理并返回候选，不调用战绩保存或原图上传接口

#### Scenario: 浏览器与超限图片
- **WHEN** 浏览器提交超限图片或未登录提交识别请求
- **THEN** 系统分别返回图片限制错误或鉴权错误，未进入 OCR 推理和业务保存流程

#### Scenario: 服务繁忙仍能填写
- **WHEN** 服务端识别最终繁忙或超时
- **THEN** 界面明确提示原因，已输入改枪码与手工属性不丢失，可继续手工保存

### Requirement: 校对确认和草稿生命周期

系统必须（SHALL）在属性保存前要求用户确认属性与当前改枪码对应，允许修改候选与补录缺失字段。识别出的枪名不同于草稿时必须提示并要求更正或明确确认。再次识别必须保留已人工修改值，覆盖全部值须显式选择。图片候选、属性编辑与确认状态必须纳入未保存保护。

#### Scenario: 枪名不一致
- **WHEN** 当前方案是 M7，但截图识别枪名为其他武器
- **THEN** 系统提示不一致，未更正或明确确认前不得接受截图属性保存

#### Scenario: 重新识别不覆盖校对
- **WHEN** 用户已将操控速度手动更正为38后重新识别
- **THEN** 系统保留38并仅填充未修改空字段，除非用户显式选择替换全部

#### Scenario: 迟到识别与退出
- **WHEN** 识别过程中用户更换截图、修改方案身份、关闭编辑器或退出账户
- **THEN** 旧识别结果不得填入新草稿或其他账号，关闭编辑器须遵循未保存确认，废弃截图预览资源被释放

### Requirement: 私有属性保存及输入校验

系统必须（SHALL）只将用户确认后的结构化个人属性保存到当前账号的改枪码记录。保存必须验证固定字段、有限非负数值、整数格式、开火模式及对应方案身份，至少包含一项主要属性；缺失字段允许为空，数值0与空值必须区分。来源必须表示个人 OCR 校对或手工录入，确认时间必须由服务器生成。

#### Scenario: 保存后重新登录
- **WHEN** 用户确认个人属性并保存成功，然后重启客户端或重新登录
- **THEN** 同账号仍能读取该方案的属性、单位、来源和确认时间，截图价格显示为历史参考价

#### Scenario: 非法属性输入
- **WHEN** 提交负数、非有限数值、非法枚举、超出保护范围、仅价格或与当前方案身份不一致的快照
- **THEN** 服务端拒绝并保持已有记录不变，不信任客户端自报第三方来源或确认时间

#### Scenario: 跨账号操作
- **WHEN** 另一账号尝试修改、清除或读取该私人记录的属性
- **THEN** 系统不返回或修改目标账号数据，保持原有账号隔离与统一不存在响应

### Requirement: 个人来源优先及清除行为

系统必须（SHALL）独立保存个人快照与第三方目录快照，展示优先级为个人快照优先。第三方未收录、不可用或新查询返回结果时不得覆盖个人属性，缺失个人字段不得自动混入目录属性。用户必须能够明确清除个人属性以恢复目录结果；仅保存个人属性不得等待第三方服务。

#### Scenario: 未收录但有个人属性
- **WHEN** 目录没有该方案，用户已确认保存个人属性
- **THEN** 列表和详情显示个人属性及来源，不再将整个方案描述为未获取属性

#### Scenario: 查询目录保留个人属性
- **WHEN** 已有个人属性的方案重新查询目录并匹配成功或失败
- **THEN** 个人值保持不变，目录结果作为另一来源保留，界面不自动覆盖个人快照

#### Scenario: 明确恢复目录属性
- **WHEN** 用户确认清除个人属性
- **THEN** 个人快照被清空，有目录快照时显示目录结果，否则显示尚未获取属性

### Requirement: 方案绑定与旧客户端兼容

系统必须（SHALL）按规范化的枪名、模式和核心码绑定个人属性。仅修改备注或改变完整码文字形式但身份不变时必须保留快照，身份改变时不得继续展示旧个人属性。旧客户端不提交个人字段时，同身份更新必须保留个人快照；明确清除与字段省略必须有不同语义。

#### Scenario: 备注更新和旧客户端省略字段
- **WHEN** 新旧客户端更新同一方案备注且没有提交个人属性字段
- **THEN** 原个人属性、来源和确认时间保持不变

#### Scenario: 更换方案核心码
- **WHEN** 用户将核心码、枪名或模式改为另一方案且未重新确认对应属性
- **THEN** 系统提醒并使旧个人快照失效，不把原属性附着到新方案

### Requirement: 内存预览与数据库存储边界

系统必须（SHALL）保证识别预览不创建改枪码、对局截图、订单流水或 OSS 对象。取消时不保存候选、原图或完整 OCR 文本；确认后仅保存结构化个人属性和必要来源时间，不保存截图、原始文字或其 OSS 副本。新增个人属性必须只存数据库，且不进入账本自动归档。

#### Scenario: 识别成功后取消
- **WHEN** 用户识别成功但放弃修改
- **THEN** 数据库原记录、截图表、对象任务和 OSS 均不产生该预览的新增内容

#### Scenario: 确认只保存属性
- **WHEN** 用户确认并保存识别后的属性
- **THEN** 仅私人改枪码结构化属性变化，图片和原始 OCR 文本未持久化，账本余额与订单进度不受影响
