## Context

PWTools 使用 React/Mantine 桌面界面与 Rust/Axum/PostgreSQL 后端。用户已明确采用三角洲数据帝服务，并提供 Token；改枪码仅存数据库，不新增 OSS 归档。公开服务查询的是已收录目录，不是任意码解码器。实测按武器名称 `n` 查询可返回相关方案及 `properties_data`。

## Goals / Non-Goals

**Goals:** 按账号管理改枪码；支持完整码及核心码；搜索、模式筛选、复制、编辑、删除；查询并保存准确匹配的方案属性。

**Non-Goals:** 本地反解任意编码、还原精校或配件、公开分享、批量导入导出、OCR、OSS 归档及自动生产部署。

## Decisions

- 私人表 `weapon_build_codes` 存原始码、核心码、武器、模式、备注、属性快照、查询状态和时间戳。所有操作以当前会话的 `user_id` 限定；不存在和无权访问统一返回 404。
- 完整码从右侧分离模式和编码，枪名可含连字符；核心码为 8–64 位 ASCII 字母数字。核心码需用户补充武器和模式。原码最多256字符，武器最多100字符，备注最多2000字符。前端解析仅作即时反馈，服务端权威校验。
- API 提供 `/api/weapon-build-codes` GET/POST、`/{id}` PATCH/DELETE、`/lookup` POST。PATCH 提交完整可编辑字段，与现有个人模板接口一致。
- 属性由服务端访问固定 HTTPS 数据帝 V2 地址，Token 从 `BUILD_CODE_API_TOKEN` 读取，客户端与源码不保存凭证。`solutionType=gun/operator` 区分模式，`n` 按武器名查询，读取所有分页后才缓存。
- 公共目录缓存表 `weapon_build_code_catalog` 按武器和模式共享，TTL为6小时，包括空结果。进程内互斥锁避免并发重复查询，整个查询限10秒，响应限2MB，每武器目录最多1200项和100页；禁止重定向。异常日志与公开错误不包含 Token 或上游请求 URL。
- 严格比较核心码、完整武器名称、模式后才保存属性；只接受已知属性数值，不使用 `zb`。快照含来源、目录实际获取时间、参考价和变化值。空结果、服务异常和未配置分别反馈，均不阻止保存。
- `WeaponBuildCodes.tsx` 使用现有主题与 Mantine 表单/弹窗，导航为「改枪码管理」。查询和保存互斥，成功后才更新列表；复制失败允许选择码手动复制，删除需确认；未保存内容参与现有导航关闭保护。
- `DesktopBridge`、浏览器封装、TypeScript 原生桥接及 C++ API 分发同步扩展，确保 Windows 客户端能请求新接口。

## Risks / Trade-offs

- 只能匹配供应商已收录方案，未收录显示无属性；不把基础枪械属性当作配装结果。
- 属性和参考价可能随版本变动；展示真实获取时间，不承诺实时价格或客户端级准确性。
- API 按成功请求消耗资源。按武器和模式缓存，分页只在缓存失效后请求；未配置 Token 仍可管理私人方案。

## Migration Plan

新建 `202610070002_weapon_build_codes.sql`，增加私人记录表、公共缓存表和索引，不修改已上线迁移，不新增归档触发器。迁移随 API 启动执行。配置 Token 后部署后端和新桌面客户端即可使用；数据库回滚须先保留私人方案数据。
